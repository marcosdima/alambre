# alambre

`alambre` is a React Native utility library focused on reusable capabilities, small UI helpers, and navigation/testing playgrounds.

It lives in a pnpm workspace monorepo. The `apps/demo` app exercises the library capabilities and components in real screens.

## Current Scope

- Content-driven capabilities that encapsulate reusable state and persistence logic:
	- `createConfigProvider`
	- `createLangProvider`
	- `createLightDarkProvider`
- Behavior providers with their own dedicated shapes:
	- `createApiProvider` (powered by TanStack Query)
	- `NavigatorProvider`
	- `ToastProvider`
- Navigation test flow with nested pages (`home`, `configuration`, `advance`, `play`, `toast`)
- Toast provider integration with queue and custom toast component support
- Theme switching (light/dark) with persisted storage
- API playground in the demo app:
	- typed route catalog
	- generated query/mutation hooks from route definitions
	- route execution demo and structured response rendering

## Project Structure (high level)

- `src/core/`: internal provisioning machinery (`createStore`, `createProvider`)
- `src/capabilities/`: content-driven providers (config, lang, light-dark)
- `src/behaviors/`: provider-shaped behaviors (api, navigator, toast)
- `src/components/`: base UI components and animations
- `dist/`: build output generated by `react-native-builder-bob`
- `apps/demo/src/providers/`: demo providers for config/lang/theme/api/toast
- `apps/demo/src/views/`: demo screens grouped by domain
- `apps/demo/src/navigator/`: demo app navigation config and root screen
- `apps/demo/App.tsx`: wires providers and demo screens together

## Architecture

The framework splits provisioning into three layers:

- `core` (internal): a small state container (`createStore`) and React Context wiring (`createProvider`). These are implementation details and are not part of the public API.
- `capabilities`: the application supplies content (config fields, language dictionaries, light/dark themes) and the framework supplies the behavior (state, storage hydration, context provider and hook). The application never writes state or provider logic.
- `behaviors`: distinct capabilities whose logic does not fit the content-driven core — API wiring over TanStack Query, navigation, and toast queueing. They share the provider/hook contract but not the internal machinery.

### Capability data flow

1. A capability builds a `createStore` from its initial content.
2. On provider mount, `createProvider` subscribes React state to the store and runs an optional `hydrate()` (loading persisted values from `Storage`).
3. Actions mutate the store via `setState(...)` and persist through the `Storage` adapter.
4. Subscribers are notified and React re-renders.
5. On unmount, the provider unsubscribes, disposes the store, and runs any cleanup.

```tsx
const { ConfigProvider, useConfig } = createConfigProvider(baseConfig, storage);
```

## Capabilities

- `config`:
	- Persists and updates simple string config fields.
	- Exposes `config` and `saveField`.
- `lang`:
	- Persists selected language key.
	- Exposes `lang`, `currentLang`, and `changeLang`.
- `light-dark`:
	- Persists current theme name (`light` or `dark`).
	- Exposes `theme`, `currThemeName`, `toggleTheme`, and `setThemeName`.

## Behaviors

- `api`:
	- Generates typed routes and query/mutation hooks.
	- Wraps TanStack Query setup and request helpers.
- `navigator`:
	- Stores page stack and scroll state.
	- Exposes navigation actions and current page metadata.
- `toast`:
	- Handles toast queue, timers, and lifecycle.
	- Renders a required client `ToastComponent`.

## Quick Start

From the repository root, install workspace dependencies:

```bash
pnpm install
```

Build the library:

```bash
pnpm --filter alambre build
```

Run the demo app (from `apps/demo`):

```bash
pnpm --filter @alambre/demo android
```

Other useful scripts:

```bash
pnpm --filter alambre lint
pnpm --filter alambre typecheck
```

## Consuming the library

Inside this workspace, apps depend on the local package with the `workspace:*` protocol:

```json
{
  "dependencies": {
    "alambre": "workspace:*"
  }
}
```

For consumption outside the workspace, publish the package from `packages/alambre`:

```bash
cd packages/alambre
npm publish
```
